#+title: Gitea 安装与配置

在 Debian 系统上以官方发布的二进制安装 Gitea（固定版本，见
=vars/main.yaml= ），由 systemd 托管，服务保持启动状态。配置文件为
=/etc/gitea/app.ini= ，由本 role 的 =templates/app.ini.j2= 渲染。

完整的部署还需要 PostgreSQL 数据库与 Caddy 反代，由 playbook
（=../../playbooks/service.yaml= ）组合：postgresql / gitea / caddy
三个 role 依次完成建库与服务部署，最后由 play 级任务把 gitea 站点
接入 Caddy——所有服务启动之后才配置反代。role 还附带每日备份并
上传 WebDAV 存档，见下文「备份」。

* 目录结构

- =/usr/local/bin/gitea= ：Gitea 二进制，从 dl.gitea.com 下载，
  sha256 校验，root 只读可执行。
- =/etc/gitea/app.ini= ：主配置文件（root:git 0640）。密钥已全部写
  明且 =INSTALL_LOCK = true= ，Gitea 启动时不会再改动它。
- =/var/lib/gitea= ：工作目录（=WORK_PATH= ），下设 =custom= 、
  =data= （=APP_DATA_PATH= ，仓库、附件等数据）、=log= ，属主为
  =git= 用户。
- =/etc/systemd/system/gitea.service= ：systemd unit。
- =/home/git/gitea-backup= ：每日备份脚本（=templates/gitea-backup.sh.j2=
  渲染），由 =gitea-backup.service= 以 git 用户调用。
- =/home/git/gitea-backup.env= ：备份凭据（git 0600），由脚本
  source（=templates/gitea-backup.env.j2= 渲染）。
- =/home/git/backup= ：dump 落盘目录（git 0700），兼作 dump 的
  tempdir 与上传失败时的积压队列，上传成功即清空。
- =/etc/sudoers.d/gitea-backup= ：放行 git 用户免密执行 systemctl
  stop/start gitea 两条命令，供备份脚本停启用服务。
- =/etc/systemd/system/gitea-backup.service= 与 =.timer= ：oneshot
  备份服务与每日定时器；unit 变更只触发 daemon-reload，不影响
  Gitea 主服务。
- =git= 系统用户：运行 Gitea 的用户（=RUN_USER= ），同时是 git
  over SSH 的登录用户；home 为 =/home/git= （官方安装教程的默认
  值），与 Gitea 工作目录（=WORK_PATH= ）是两个路径。

* 变量

必填变量（无默认值，由引用方 playbook 提供，未提供时模板渲染报错）：

- =gitea_internal_token=
- =gitea_domain=
- =gitea_lfs_jwt_secret=
- =gitea_oauth2_jwt_secret=
- =gitea_db_name= 、=gitea_db_owner= 、=gitea_db_owner_password=
- =gitea_webdav_url= 、=gitea_webdav_user= 、=gitea_webdav_password=
  （备份上传的 WebDAV 端点与凭据，见「备份」）

默认变量（有默认值，见 =defaults/main.yaml= ，可覆盖，此处不列默认
值）：

- =gitea_http_port= ：Gitea 的 HTTP 监听端口（app.ini 的
  =HTTP_PORT= ），反代指向它。

站点相关设置除上述变量外均写在 =templates/app.ini.j2= 里，改配置
直接改模板（改后重跑 playbook 会触发重启）。=vars/main.yaml= 是
内部常量（版本、下载地址、路径、用户名），任务与 systemd unit 从
那里取值；app.ini 中的路径同样由这些常量拼接，与任务、unit 自动
保持一致。

* 升级

修改 =vars/main.yaml= 中的 =gitea_version= ，重跑 playbook 即可：
sha256 从下载地址旁的 =.sha256= 文件自动获取，二进制变化会触发服务
重启。跨大版本升级先读官方 release notes 确认无破坏性变更。

* 备份

role 附带每日备份（=tasks/backup.yaml= 部署），=gitea-backup.timer=
每天 04:00 触发（OnCalendar 按系统时区解释，主机时区为
Asia/Shanghai；=RandomizedDelaySec= 错开两台 VPS，=Persistent= 在
关机错过触发点时补跑）。流程：

1. sudo 停 Gitea，停服窗口开始，web 与 git over SSH 均不可用；
2. =pg_dump= 导出数据库（MVCC 快照在线导出，无需停 PostgreSQL；
   此时 Gitea 已停、无新写入，快照即停机时刻内容）；
3. =gitea dump= 打包全量数据（数据库 xorm 导出、仓库、LFS、附件、
   app.ini）为 zip；
4. pg_dump 的 SQL（=gitea-db.pg_dump.sql= ）追加进 zip 根目录，zip
   即完整；
5. 立即重启 Gitea——停机窗口只覆盖 dump 阶段；
6. rclone 上传 =backup= 目录下所有 zip（含上次上传失败留下的积压）
   到家里机器 WebDAV（=dav.<域名>= ，Caddy 反代经 frp 隧道，落到
   专用 =git= 用户的目录下，文件名
   =gitea-dump-<主机名>-<时间戳>.zip= ），
   成功即删本地，失败保留、退出码非 0 让 systemd 标记失败，次日
   连同积压一起补传；远端永久保留，不自动清理。

无论哪一步失败，脚本的 EXIT trap 都会把停着的 Gitea 拉起来，并清掉
本轮未完整生成的 zip/SQL（完整生成的 zip 保留待补传）。

- 备份凭据（WebDAV 与数据库）在 =/home/git/gitea-backup.env= （git
  0600），由脚本 source。密码不写 rclone.conf：rclone obscure 每次
  输出都不同（随机 IV），渲染进配置文件会破坏 playbook 幂等；脚本
  在运行时经 stdin 生成 obscured 密码、以环境变量定义 remote，不落
  任何 rclone 配置文件。
- 上传失败会在 =/home/git/backup/= 积压 zip，磁盘占用随失败天数线性
  增长，journal 有对应失败记录，需偶尔检查清理。
- 恢复：zip 内 =gitea-db.sql= 是 Gitea xorm 导出，按官方文档
  https://docs.gitea.com/usage/backup-and-restore 恢复；
  =gitea-db.pg_dump.sql= 是 pg_dump plain SQL，用 psql 导入即可。
  建议做过恢复演练后再依赖此备份。

手动触发与排查：

#+begin_src shell
systemctl start gitea-backup.service   # 手动跑一次
journalctl -u gitea-backup.service     # 看日志（dump 与上传都在这）
systemctl list-timers gitea-backup*    # 看下次触发时间
ls /home/git/backup/                   # 看本地积压
#+end_src

* 注意

- PostgreSQL 角色与数据库由 playbook 以 postgresql role 创建：
  playbook 以本 role 的 =gitea_db_*= 变量构造其参数（app.ini 的
  =[database]= 引用同一组变量），两处天然一致。
- Caddy 反代在 playbook 的 tasks 阶段接入（三个 role 之后执行，保证
  各服务已启动）：站点内容内联在 playbook 中，写入
  =/etc/caddy/sites.d/gitea.caddyfile= （域名取自 =gitea_domain=
  、端口取自本 role 的 =gitea_http_port= ），import 行不带
  =managed-by=caddy-role= 标记，不参与 caddy role 的差集清理，与
  其他站点的接入方式一致。站点文件用固定名 =gitea= 而非域名：换
  域名时只更新内容，不残留旧文件。
- git over SSH 走系统 sshd（=START_SSH_SERVER = false= ），=git=
  用户的 shell 为 /bin/bash（role 已设置）；若 sshd 配置了
  =AllowUsers= 需加入 =git= 用户。app.ini 的 =SSH_PORT= 是界面上
  展示的 clone 端口，与 sshd 实际监听端口不一致时改它。
- 安装的是固定版本二进制，不随 apt 更新，升级方式见上文。
